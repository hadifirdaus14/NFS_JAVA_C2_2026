# Day 16 Exercise 5 - Before/After Diff Rationale

## Scenario

A refactor is only useful if the team understands what changed and why.

## Task

Create a Markdown file:

```text
docs/day16-ticket-refactor-rationale.md
```

## Include

- Files changed
- What behaviour was preserved
- What logic was extracted
- Why the new version is easier to maintain
- What tests or HTTP requests were run
- Any risk that still remains

## Expected output

A short but clear rationale that can be reviewed by another developer.
