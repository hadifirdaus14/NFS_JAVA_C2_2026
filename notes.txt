================================= KEY CONCEPTS =================================

1. Authentication vs Authorisation
Authentication: Who are you? e.g. A user who logins successfully.
Authorisation: What are you allowed to do? The user might not be allowed to create/delete items.

2. Password hashing
NEVER store passwords in plain text
User pwd -> BCrypt hashing -> passwordHash stored in the db
Whenever a user logs in, Spring Security compare the entered pwd against the stored hash

3. JWT idea
JWT JSON Web Token
Server give the client a signed token after login
Client send the token in later requests
Server check the token before allowing any access

4. Client sends a token like this
Authortization: Bearer <token>

401 vs 403
401 Unauthorised. User not logged in, or token is missing/invalid
403 Forbidden. You are logged in, but your role is not allowed to do a certain action

USER and ADMIN
USER = View assets
ADMIN = view and create assets

Seed an admin user
Normal registration creates USER account only



===================================== Day 10: API Quality: Versioning, Docs, Aggregation =====================================

What does API quality mean?
An API is not only good because it works. It's good when it is:
    1. Predictable
    2. secure
    3. Documented
    4. Versioned
    5. Tesable
    6. Consistent

VERSIONING
Means putting a version number in the API path
/api/v1/assets
This allows future changes without immediately breaking older clients

DOCUMENTATION
Documentation tell devs:
1. What endpoints exist?
2. What method to use?
3. What authentication is needed?
4. What does each endpoint do?
JSON documentation endpoint
GET /api/docs

AGGREGATION
Means asking the db to calculate a summary
Example: Count number of assets by status 
Instead of downloading every asset and counting in JavaScript, MongoDB groups and count the records

ERROR CONTRACT
A good API should return consistent errors
{
    "message": "Error message goes here", 
    "status": 400, 
    "timestamp": "YYYY-MM-DD-HH-mm-ss"
    "errors": []
}
